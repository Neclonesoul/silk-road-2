# Cloudflare production deployment

Run commands from the repository root. Replace resource identifiers and public values deliberately; never commit secrets.

## 1. Prerequisites

- Node.js 20.19+ (Node 22 LTS recommended)
- npm
- a Cloudflare account with Workers, D1, R2 and Durable Objects available
- Wrangler authentication (`npx wrangler whoami`)
- a transactional email domain/provider if public password recovery and email verification must deliver

## 2. Install and validate

```sh
npm ci
npm run qa
```

## 3. Create D1

```sh
npx wrangler d1 create silk-road-db
```

Copy the returned `database_id` into `wrangler.jsonc`. Keep binding `DB` and database name `silk-road-db` unchanged unless all code and documentation are updated together.

Apply migrations:

```sh
npx wrangler d1 migrations apply silk-road-db --remote
```

Confirm both `0001_initial.sql` and `0002_admin_guard.sql` were applied.

## 4. Create R2

```sh
npx wrangler r2 bucket create silk-road-media
```

The bucket is private. Listing media is served through `/media/*`, which performs database visibility checks. Do not attach a public R2 domain for V1.

## 5. Durable Objects

No separate object instance creation is required. Keep the `CHAT_ROOMS` binding, `ChatRoom` class export and `v1` SQLite-class migration in `wrangler.jsonc`. Wrangler provisions the namespace during the first deployment. Do not remove a deployed Durable Object migration tag.

## 6. Public configuration

Edit the non-secret `vars` in `wrangler.jsonc`:

- `PUBLIC_APP_NAME`
- `PUBLIC_APP_SHORT_NAME`
- `PUBLIC_APP_DESCRIPTION`
- `PUBLIC_APP_URL` — final HTTPS origin, with no trailing slash
- `PUBLIC_SUPPORT_EMAIL`
- `SESSION_COOKIE_NAME`
- `APP_ENV=production`

Brand defaults also live in `src/lib/config.ts`; change them before release if the public product name changes.

## 7. Secrets

Required for a public launch:

```sh
npx wrangler secret put TURNSTILE_SECRET_KEY
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put EMAIL_FROM
npx wrangler secret put ADMIN_EMAILS
npx wrangler secret put LEGAL_OPERATOR_NAME
npx wrangler secret put LEGAL_OPERATOR_ADDRESS
```

`ADMIN_EMAILS` is a comma-separated allowlist. A matching email receives the `admin` role when that account signs up. Set it before creating the first operator account. `EMAIL_FROM` must be a sender accepted by the configured Resend account. If another email provider is chosen, replace only the boundary in `src/lib/server/email.ts` and test verification/reset delivery.

Set the public Turnstile site key as a Worker variable named `PUBLIC_TURNSTILE_SITE_KEY` using the Cloudflare dashboard or `wrangler.jsonc`.

## 8. Deploy

```sh
npm run qa
npm run deploy
```

The build creates `.svelte-kit/cloudflare/_worker.js` and deterministically appends the `ChatRoom` export. Wrangler bundles this generated entry point and uploads static assets. Do not commit `.svelte-kit`; it is regenerated by `npm run build`.

## 9. Custom domain

In Cloudflare Dashboard: **Workers & Pages → silk-road-2 → Settings → Domains & Routes → Add → Custom domain**. Add the intended hostname, then update `PUBLIC_APP_URL` and redeploy so canonical, Open Graph, sitemap and verification/reset URLs match production.

## 10. First administrator and first listing

1. Confirm `ADMIN_EMAILS` contains the operator email.
2. Sign up with that exact email.
3. Verify the email delivery and link.
4. Open `/admin` and confirm server-authorized access.
5. Open `/sell`, create a real draft, upload real photos, save and publish.
6. Inspect the public detail page in a signed-out browser.

## 11. Live smoke test

- `GET /api/health` returns `status: ok`, `database: ok`, `version: 2.0.0`.
- Signed-out home/search/terms/privacy render.
- Signup, verification, login, logout, forgot/reset and cookie security work.
- Seller creates, edits, publishes, reserves and sells a listing; non-owner access is rejected.
- Images upload, order, cover, remove and public delivery work.
- Buyer favourites and contacts a seller; both sides exchange realtime messages.
- Report and block work; admin resolves a report and removes a test listing.
- PWA installs; offline route appears without caching private state.

## 12. GitHub Actions

Repository secrets:

- `CLOUDFLARE_API_TOKEN` — least-privilege Workers/D1/R2/Durable Objects deployment token
- `CLOUDFLARE_ACCOUNT_ID`

CI validates every push/PR, including the mobile and desktop Playwright journeys against a migrated local D1 database. Production deployment is manual through the `Deploy production` workflow and reruns QA and browser journeys before deploying.

## Rollback

Cloudflare Worker versions are immutable. Use the dashboard version history to roll back application code immediately. Do not reverse a D1 migration blindly. See [docs/RUNBOOK.md](docs/RUNBOOK.md) for the coordinated code/schema rollback procedure.
